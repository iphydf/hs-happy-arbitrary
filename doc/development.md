# Development Guide

This document outlines the workflow for developing `hs-happy-arbitrary`.

## Prerequisites

*   **Bazel**: The project is built using Bazel. Ensure you have it installed.
*   **GHC**: The Glasgow Haskell Compiler is required for building Haskell code.

## Building the Project

To build the entire project, run:

```sh
bazel build //hs-happy-arbitrary:all
```

To build a specific library (e.g., the parser):

```sh
bazel build //hs-happy-arbitrary:parser
```

## Running Tests

The project uses `hspec` for testing.

### Run All Tests

To run the complete test suite:

```sh
bazel test //hs-happy-arbitrary:testsuite
```

### Run Specific Tests

To run a specific test module or case, use the `--test_arg=--match=...` flag.

**Example: Run only Boltzmann Solver tests**

```sh
bazel test //hs-happy-arbitrary:testsuite --test_arg=--match=Boltzmann --test_output=all
```

**Example: Run Arbitrary Generation tests**

```sh
bazel test //hs-happy-arbitrary:testsuite --test_arg=--match=Arbitrary --test_output=all
```

## Project Structure

*   `src/`: Source code.
    *   `Language/Happy/`: Happy grammar parser and generator logic.
    *   `Language/Alex/`: Alex lexer parser (used for future linking).
*   `test/`: Test suite.
    *   `testsuite.hs`: Main test entry point.
    *   `Language/Happy/`: Unit tests for specific modules.
*   `BUILD.bazel`: Bazel build configuration.
*   `happy-arbitrary.cabal`: Cabal package description (kept in sync with Bazel).

## Key Modules

*   `Language.Happy.Boltzmann`: Implements the Boltzmann sampling logic for weighted grammar generation.
*   `Language.Happy.Arbitrary`: The main entry point for generating arbitrary tokens from a grammar.
*   `Language.Happy.Ast`: AST definitions for parsed Happy files.
*   `Language.Happy.Parser`: The parser for `.y` files (generated by Happy).
